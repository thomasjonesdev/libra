# 12.5 Declarative Subscriptions

## In this vault

- Parent: [[12-effects-runtime]]

## In code

- `crates/libra-components/src/catalog/source.rs` — source elements (`<Frames>` / `<Interval>` / `<Stream>`), build-only mount nodes
- `crates/libra-platform/src/lib.rs` — display loop: while `<Frames>` / `Sub::Frames` **or a live data-plane source** is mounted, `ControlFlow::Poll` + refresh-cadence ticks in `about_to_wait` (browser rAF; developers only mount `<Frames/>`). `sync_subscriptions` runs **after** relayout collects handlers. `<Interval>` = dedicated timer threads.
- `crates/libra-data/src/lib.rs` — `SeriesStore::has_live_ingest()`, the live-data-plane term of the display loop.

---

The React instinct this serves is `useEffect`'s legitimate core: *"while this UI is on screen, keep X running."* Libra's answer keeps it data. A closed set of **source elements** may appear in markup; they render nothing, occupy no layout, and declare an ongoing source:

```jsx
<if test={running}>
  <Frames onTick={frame} />                      // vsync ticks while mounted
  <Interval every={1000} onTick={poll} />        // ms; literal or binding
  <Stream id={telemetryFeed} onEvent={packet} />
</if>
```

Semantics:

- **Mount = subscribe, unmount = cancel.** After each commit the runtime collects mounted source elements from the ViewTree, unions them with `subscriptions(state)` ([[12.2-subscriptions|§12.2]]), and diffs the union against the running set — start new, cancel removed. Identity is (element kind, resolved props): the moral equivalent of a React dependency array, diffed by the runtime instead of managed in userland.
- **Purity is preserved, not spent.** Views are pure projections of state, so the mounted set is itself a pure function of state — exactly the property [[12.2-subscriptions|§12.2]] already requires. Neither engine *executes* anything at build: interpreter and codegen both fold source elements into inert data nodes, conformance-covered per [[06.4-one-grammar-two-engines|§6.4]].
- **The closed grammar holds.** Props are literals or bindings, nothing computed — a per-series `SourceSpec`, a backoff policy, anything parameterized stays in actions or `subscriptions(state)`. The element set (`Frames`, `Interval`, `Stream`) is closed like the rest of the catalog.
- **Results are ordinary actions.** Ticks and events arrive through the recorded channel, so replay, time travel, and sequence fuzzing see them like every other action; `fire_timer`/`dispatch` drive them in tests unchanged.
- **Testable as data.** Source elements appear in the semantics tree under a test-only role (excluded from the AccessKit projection): `h.get(by::source("frames")).assert_mounted()` is a component-test assertion, and a paused dashboard asserts the absence.
- **Snapshot-neutral by construction** — no DrawCmds, no layout node — and hot reload re-diffs declarations like any other view edit: state preserved, sources started or cancelled to match the new markup.
- **A live data plane drives the display loop by itself.** `<Frames>` is a *pump* — for the common "show a streaming series" case the app shouldn't have to wire one. The windowed shell arms the same refresh-cadence loop while `SeriesStore::has_live_ingest()` is true, so a `<Chart>`/`<Sparkline>` bound to an open ingest source animates with **no `<Frames>` in the view**; pause = `IngestClose` drops the term and the loop idles (the last frame stays on screen). `examples/dashboard` and `examples/gallery` both rely on this — neither has a `<Frames>` element. This is the §14.2 data-plane exception (charts read the ring at paint) made ambient: *when the data plane is live, the view repaints*. Determinism holds — the harness's synchronous `feed_tape` registers no source, so tests never auto-tick and snapshots stay byte-exact. Reserve `<Frames>` for when a **frame tick must change state**, not merely repaint (a clock label, a computed animation) — never as a repaint pump for live data.

**Implemented today:** `<Frames>`, `<Interval>`, and `<Stream>` are live. `Effect::Spawn` delivers lines to the mounted handler ([[PLAN-STREAM-DELIVERY]]). `Sub::Stream` unions with markup: markup wins when both name the same id. A hidden window (close-to-tray) still delivers. Hiding does not unmount sources.

What this is **not**: hooks as code. No state lives in the tree, nothing executes at render, and there is no user-supplied closure — a declaration names an action; the runtime owns the lifecycle. (Markup-declared *queries* — `<Query>` à la Relay — would ride the same mechanism but need dedup/waterfall design with `libra-query`; deferred, see [[26-open-questions|§26]].)
