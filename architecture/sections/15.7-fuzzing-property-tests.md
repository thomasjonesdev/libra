# 15.7 Fuzzing & Property Tests

## In this vault

- Parent: [[15-testing]]

---

- **Action-sequence fuzzing**: `proptest` generates action sequences (and adversarial effect-result orderings per [[12.3-execution-model|§12.3]]) against invariants (`no panic`, `state.validate()`, "paused chart never advances").
- **Markup fuzzing**: hostile `.lx` corpora against the parser (must never panic, must always span-diagnose).
- **Text hostile corpus**: bidi, ZWJ sequences, combining-mark storms, 10MB single lines through Input/LogView.

## Autopilot — the interaction-level form

`Harness::autopilot(steps)` ([[PLAN-AUTOPILOT]]) supplies the input side at the
layer above generated actions: it discovers affordances from the laid tree,
drives them with a seeded PRNG, and checks invariants. Generated interactions
only ever reach states a user can reach, which is what makes the failures worth
fixing.

```rust
h.autopilot(500)
    .invariant("no work left queued", |s: &App| s.pending == Pending::None)
    .always("draft tracks selection", |s: &App| s.draft == stem(&s.selected))
    .bounded("history", 500, |s: &App| s.history.len())
    .budget(Budget::new().p95_ms(150.0))
    .run();
```

Three properties carry it:

- **A run is a pure function of its seed** — a failure prints one, and the seed
  is enough to get the failure back.
- **Effects are answered in a seeded shuffle**, per [[12.3-execution-model|§12.3]].
  Emission order is the one arrangement production never promises.
- **Runs burst by default** — a few interactions land with effects still in
  flight, so the checks see the windows a settled assertion cannot. Hence the
  split between `invariant` (holds at rest) and `always` (holds after every
  step); the second is where the interesting failures are.

Effects are still intercepted — a `.responder(…)` answers effect *kinds* with
fixtures so a run can take steps whose I/O it could not enumerate in advance.
Nothing executes, so this stays inside [[15.1-determinism-contract|§15.1]] and
runs in the default suite. Real-I/O soak runs are `#[ignore]`d and exist only
for bugs *inside* the effects runtime.
