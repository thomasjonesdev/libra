# 7.2 Composed Components

**Implemented (2026-07-21, [[PLAN-COMPOSE]]):** `<props …/>` component files (optional empty props), PascalCase call sites, prop-only scope, auto-discovery from the view directory, single `{children}` slot, multi-root bodies spliced at call sites, both engines + `composed`/`slot_host` conformance fixtures; `examples/gallery` canvas blocks refactored into `views/demos/*_demo.lx` with byte-identical workbench snapshots.

---

A `.lx` file with a props declaration is a component:

```jsx
// src/views/metric_card.lx
<props label: String, value: String, trend: Trend />

<Card padding={12}>
  <Text muted size="sm">{label}</Text>
  <Row gap={8} cross="baseline">
    <Text size="xl" mono>{value}</Text>
    <TrendArrow trend={trend} />
  </Row>
</Card>
```

Props are typed; codegen validates every `<MetricCard …/>` call site.

Props are the **encapsulation boundary**: inside a component, bindings and
handlers resolve only against its props, never app State — so a component is
reusable and dispatches only the handler props passed in (the closed action set
holds). Composition is pure tree substitution before layout: a composed view
produces byte-identical `ViewNode`s to the hand-inlined equivalent, so it costs
nothing on the determinism paint path. Staging, grammar, and diagnostics →
[[PLAN-COMPOSE]].
