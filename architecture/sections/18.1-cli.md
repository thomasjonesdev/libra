# 18.1 The CLI

## In this vault

- Parent: [[18-developer-experience]]

## Vision

```
libra new <app>        scaffold (managed build — no build files to maintain)
libra dev              run with hot reload + inspector + automation server
libra check            validate all .lx + libra.toml + a11y audit, <100ms, no build
libra test             all five [[15-testing|§15]] kinds; see the runner below
libra build            release binary (codegen engine, LTO)
libra icon             one square PNG → desktop icon set ([[20-packaging|§20]])
libra package          platform bundles ([[20-packaging|§20]]); the local backup
libra publish          upload that bundle, or write the release workflow
libra fmt              canonical .lx formatting
libra skills           emit agent-skill bundle ([[16-automation-server|§16]])
```

The CLI owns the build graph for the default path; `libra eject` writes a plain Cargo workspace you own thereafter.

## Implemented today ([[PLAN-SDK]] S3)

| Command | What it does |
|---|---|
| `libra new <path>` | Write the `templates/app` starter. `--path` (a Libra checkout) or `--git <url>`. Default: path deps when this CLI was built inside the checkout, otherwise crates.io `libra-ui` at the CLI's version. No dummy `[workspace]` table. The crates.io package is `libra-ui-cli`; the binary is `libra` |
| `libra check [paths…]` | Parse every `*.lx` under the paths. **No path = the workspace containing cwd** (everything). A path is a scope: `libra check templates/app`. Grammar only — no State binding, no `libra.toml`, no a11y |
| `libra dev [path]` | Debug supervisor around `cargo run --manifest-path`. **Path-based, not `-p`.** `.lx` and theme TOML reload in the running process. A change to `src/**/*.rs`, `build.rs`, `Cargo.toml`, or `Cargo.lock` snapshots the model, stops the process group, and runs `cargo` again; the new process restores the snapshot field by field (§18.2). From this repo: `libra dev examples/counter` or `libra dev templates/app`. `-p` is forwarded to cargo and does not select a workspace package |
| `libra build [path] [-p crate]` | Release binary. Pins `--manifest-path` to the resolved workspace root (same as `package`). A package with no `[workspace]` ancestor, or a non-member under a parent workspace, is its own implicit workspace |
| `libra icon <png> [-o dir]` | One square PNG (at least 512 px, 1024 preferred) → `icon.png`, `icon.icns`, `icon.ico`, and hicolor sizes. Desktop only |
| `libra package [path] [-p crate]` | OS bundles from `libra.toml`. Same workspace rule as `build`. This is the local backup: it never calls `gh`. Ad-hoc sign when `[package.sign.macos]` is absent; Developer ID + the keychain notary profile when it is set |
| `libra publish [path] [-p crate]` | Upload `dist/` to the `[package.publish]` GitHub repo, plus `latest.json` when `[package.update]` is set. `--no-upload` writes the feed and stops. `--from-dist` skips packaging. `--ci` writes `.github/workflows/release.yml` and stops. `--keygen` prints the update keypair. The private key is `LIBRA_UPDATE_KEY` and is never committed |
| `libra test [path] [FILTER…]` | Test runner (below). **No path = the whole workspace.** A path that names a crate or `Cargo.toml` is a scope and pins `--manifest-path` — `libra test templates/app`, `libra test examples/counter`. Other positionals stay name filters (`libra test Button`) |

**Not implemented:** `libra eject`, `libra fmt`, `libra skills`, inspector, automation server. `libra new` is S3 ([[PLAN-SDK]]).

An app crate does not have to be a member of *this* workspace. `templates/app` is in the root `exclude` list (path-depends on `crates/*`) and is its own implicit workspace so the CLI can find it. First-party apps in `applications/` stay members ([[27-first-party-applications|§27]]).

### `libra test` — the runner ([[PLAN-TEST-CLI]])

The transparent front door to the whole SDK's tests: a vitest-shaped
runner over the workspace, backed by `cargo nextest` (filtering,
parallelism, reporter) + `cargo llvm-cov` (coverage). Both are detected
at start; if missing, the CLI prints an install hint and falls back to
plain `cargo test` (no coverage) — never a hard dependency.

```
libra test [path] [FILTER…]       no path = workspace; a crate path is a scope
                                  (`libra test templates/app`). Other positionals
                                  are substring filters (`libra test Button`)
  -p, --package <crate>           scope to one crate/app (repeatable)
  --kind <k>                      unit | component | integration | snapshot
  --component <Name>              gallery workbench + component tests for one component
  --coverage[=actions|full|off]   default = actions ([[15.8-ci-shape|§15.8]]); off skips it
  --no-coverage                   alias for --coverage=off
  --watch                         re-run on file change (coverage forced off)
  --validate                      re-record snapshots (LIBRA_VALIDATE=1)
  --trace-matrix[=<out>]          REQ→test→artifact JSON+HTML ([[15.8-ci-shape|§15.8]])
  -- <extra nextest args>         escape hatch
```

`--replay <file>` remains reserved (replay tests
[[15.6-replay-tests|§15.6]] aren't built yet).
