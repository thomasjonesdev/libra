# 5.2 What the macro generates (one expansion, no magic)

## In this vault

- Parent: [[05-state-and-actions]]

---

`#[libra::actions]` expands to exactly the substrate the framework has always run on — the Elm loop, generated instead of hand-written:

```rust
/// A closed, serializable event set: one variant per action;
/// method parameters become the payload.
#[derive(Clone, Debug, Serialize, Deserialize)]
pub enum Action {
    Increment,
    Decrement,
    FilterChanged(String),
    Connect,
    SessionLoaded(HttpResult),
    Frame(FrameInfo),
}

/// The reducer: the only place state changes.
pub fn reduce(state: &mut AppState, action: Action) -> Vec<Effect> {
    match action {
        Action::Increment => { state.increment(); vec![] }
        // … one arm per action
    }
}
```

Everything downstream operates on `Action` values — the action log, time travel ([[05.6-time-travel-and-replay-as-a-consequence|§5.6]]), replay tests ([[15.6-replay-tests-recorded-sessions|§15.6]]), automation dispatch ([[16-the-automation-server|§16]]), sequence fuzzing ([[15.7-fuzzing-and-property-tests|§15.7]]) — so the ergonomic layer costs nothing in determinism, replayability, or runtime overhead. Reflection for markup handler binding and the automation schema derives from the same expansion (subsuming the standalone `LibraReflect` derive).

**Dispatchability rule.** A method whose parameters are markup-expressible (none, or control payloads: `String`, `bool`, ids) is a **handler** — bindable in `.lx` under its camelCase public name ([[03.3-naming-conventions-reacts-verbatim|§3.3]]): `onPress={increment}`, `onChange={filterChanged(value)}`. A method taking an effect-result type (`HttpResult`, `KvResult`, `io::Result<…>`) is a **continuation** — constructed only by the runtime delivering that result, never by name. This is the unit-variant/payload-variant split the reflect layer already enforced, now derived from signatures instead of maintained by hand.

Hand-writing `Action` + `reduce` remains fully supported — it is literally the expansion output, and slices with intricate cross-field transitions sometimes prefer it. The macro is sugar; the contract is the enum and the reducer.
