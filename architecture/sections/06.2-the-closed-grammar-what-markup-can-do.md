# 6.2 The closed grammar — what markup CAN do

## In this vault

- Parent: [[06-the-view-layer-and-markup]]

---

- **Bind** state fields and paths: `{count}`, `{user.name}`, `{items.len()}` (a fixed whitelist of pure accessors: `len`, `isEmpty`, formatting — camelCase in markup per [[03.3-naming-conventions-reacts-verbatim|§3.3]]). Collection fields (`Vec<T>`) bind as iterable paths for `<for>`; there is no index expression (`{series[3]}` is not grammar — iterate, or model a named field).
- **Dispatch** actions by name, with payloads from bindings or literals: `onPress={increment}`, `onChange={filterChanged(value)}` (`value` is the control-provided payload), `onPress={select(item.id)}`. Handlers bind to the reflected action names of [[05.2-what-the-macro-generates-one-expansion-no-magic|§5.2]], exposed in camelCase per [[03.3-naming-conventions-reacts-verbatim|§3.3]] (`fn filter_changed` binds as `filterChanged`).
- **Declare** ongoing sources: `<Frames onTick={frame} />`, `<Interval every={1000} onTick={poll} />`, `<Stream id={feed} onEvent={packet} />` — invisible source elements, subscribed while mounted, cancelled on unmount ([[12.5-declarative-subscriptions-effects-as-mount-scoped-data|§12.5]]).
- **Conditionals**: `<if test={connection.isLive()}>…<else>…</if>` — tests are bindings or whitelisted predicates; enum variants get generated `is*` predicates (camelCase in markup, [[03.3-naming-conventions-reacts-verbatim|§3.3]]).
- **Iteration**: `<for each={items} as="item" key={item.id}>…</for>` — `key` is required when the collection can reorder; the reconciler uses it for identity.
- **Composition**: `<LogPanel entries={log.visible} onSelect={logSelected} />` — invoking another `.lx` view or Rust component with typed props.
- **Slots**: `<Card><slot/></Card>` children pass-through.
- **Format strings**: `{count:>6}` / `{temp:.2}` — Rust `format!` spec subset, compiled, no runtime parse.

---

## Implemented today (vs the vision above)

The bullets above are the target grammar. What both engines actually support now:

- **Bind**: whole-value fields `{count}` / `{name}`. No accessor whitelist (`{items.len()}`) and no dot-paths (`{user.name}`) yet — model the derived value as a named State field ([[06.3-what-markup-cannot-do-and-why-each-restriction-pays|§6.3]] projections, rebuilt automatically by the `#[project]` hook).
- **Dispatch**:
  - unit handlers `onPress={increment}`;
  - control-payload handlers `onChange={draftChanged}` (the control supplies the `String`);
  - **item-scoped handlers `onPress={toggle(loopVar)}`** — the loop binding's Display becomes the action's `String` payload. Parsed as `AttrValue::Call` (libra-markup), resolved and validated (must be a `String`-payload action, arg must be in scope) in both engines, carried on `ViewNode::Button.on_press_arg` → `Item.on_press_arg`, dispatched via `ReflectAction::action_with_str` by harness and shell. The `for_actions` conformance fixture is the drift guard. *Not* yet: dot-path args (`select(item.id)`) — the arg must be a whole in-scope binding.
- **Iterate**: `<for each={items} as="x" key={x}>` where `key` must be the loop variable itself (no `key={x.id}` — no reconciler yet; identity must be encoded in the item's Display string). Items are whole-value Display strings; no `{x.field}` sub-binding.
- **Not built**: `{item.field}` dot-paths, accessor whitelist, `<if>`/`<else>` conditionals (§26), `<Interval>`/`<Stream>` sources (§12.5), composition/slots.

`examples/todos` is the reference for item-scoped handlers; `examples/dashboard` for display-only `<for>`.
