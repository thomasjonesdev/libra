# 18.4 Debugging

## In this vault

- Parent: [[18-developer-experience]]

## In code

- `crates/libra-platform/src/inspector.rs` — action log + state window
- `cli/libra/src/dev.rs` — sets `LIBRA_INSPECTOR=1`

## Implemented today

`libra dev` opens a second window titled **Libra Inspector** beside the app (debug builds only). It lists bindable state and the recent action log. The log is a ring of 48. Identical neighbors collapse, so a `<Frames>` pump stays one line (`Ticked × N`). `#[libra(redact)]` fields appear as `(redacted)` in the window; their values still stay off the automation `state` verb. The same log is the automation `log` verb. The window is not part of the app display list.

Still open on this note: component tree with geometry, damage-rect visualization, layer-cache view, frame timings inside the inspector. `LIBRA_FRAME_STATS` remains the stderr pacing line. Standard Rust debugging applies to actions and components (lldb/gdb, `dbg!`), because they are plain functions.
