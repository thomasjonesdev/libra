# 18.6 Editor Tooling

## In this vault

- Parent: [[18-developer-experience]]

## In code

- `editors/vscode/` — TextMate grammar + language config (Day 1)
- `editors/README.md` — install for Cursor / VS Code / other editors

---

- **Day 1**: full rust-analyzer for all logic; TextMate grammar for `.lx` (syntax highlight in VS Code/Zed/Helix — an afternoon); `libra check` on save. **Shipped:** `editors/vscode/` — TextMate grammar + language config for Cursor/VS Code (`./editors/vscode/install.sh` to symlink; see `editors/README.md`). Scope `source.lx`; catalog / `for`·`if`·`else` / sources / bindings / handler calls.
- **v0.2 diagnostics shipped:** `libra lsp` speaks stdio JSON-RPC. `textDocument/didOpen` and `didChange` (full sync) publish diagnostics from `libra_interp::diagnose`: parse errors, unknown elements, bad attributes, PascalCase handlers. Spans are the parser's 1-based line/col, sent as 0-based LSP positions. The scope accepts every binding and every camelCase action, so a missing State field is not reported yet. Completion, hover, and go-to-definition (binding → State field, handler → Action variant) stay open — they need the app's reflected types.
