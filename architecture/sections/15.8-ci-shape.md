# 15.8 CI Shape

## In this vault

- Parent: [[15-testing]]

---

`cargo test` runs all five kinds on a bare `ubuntu-latest` — no Xvfb, no GPU, no browser. Snapshot artifacts upload on failure. That job proves the **paint** path ([[09.2-canonical-executor|§9.2]]): a Linux-recorded PNG must match macOS and Windows. It does **not** prove windowed chrome (menus, clipboard, dialogs, tray). Those stay on the [[19.4-desktop-os-matrix|§19.4]] matrix and land with harness coverage plus a native check on each host — do not treat missing windowed CI as permission to leave a silent no-op. `libra test` ([[18.1-cli|§18.1]], [[PLAN-TEST-CLI]]) is the canonical entry (CI may still invoke `cargo test` directly); it is backed by `cargo nextest` + `cargo llvm-cov`.

Coverage of the actions layer is meaningful line coverage of actual behavior, reportable against requirements — so it is the **default** of `libra test` (`--coverage=actions`): the runner filters the llvm-cov export to each app's `actions.rs` / `#[libra::actions]` impls, with `--coverage=full` for whole-workspace line coverage. Traceability is first-class: tests carry `#[libra::verifies("REQ-UI-042")]` annotations — a **pass-through** attribute (added in `libra-reflect`, re-exported via the `libra` facade) that the runner reads from source. `libra test --trace-matrix` emits requirement → test → artifact (snapshot PNG / replay hash) as JSON+HTML — the evidence bundle compliance postures like NPR 7150.2 or DO-178C-adjacent processes ask for, generated from the suite that already runs in CI. External traceability harnesses consume the same JSON.
