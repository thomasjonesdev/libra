# 5.8 App Assembly

## In this vault

- Parent: [[05-state-and-actions]]

## In code

- `crates/libra-reflect/src/app.rs` — the `app!` macro (state/view/window/title/init/subscriptions/shortcuts/menu)

---

Everything outside state and actions is wiring, and wiring is generated. A complete app crate:

```rust
#[libra::state]
pub struct Counter { pub count: i64 }

#[libra::actions]
impl Counter {
    pub fn increment(&mut self) { self.count += 1; }
    pub fn decrement(&mut self) { self.count -= 1; }
    pub fn reset(&mut self)     { self.count = 0; }
}

libra::app! {
    state: Counter,
    view: "../views/counter.lx",    // relative to this .rs file (`include_str!`)
    window: (400.0, 240.0),         // optional; libra.toml wins when both exist
    title: "Libra Counter",
}
```

`app!` generates the wiring and nothing else: the `App` impl (init from `State::init()`, falling back to `Default`), the **view bundle** (the watched dev path and the `include_str!` release embedding, from one declaration), and the windowed entry points `run()` + `options()` (a bin crate's `main.rs` is a one-line call to `run()`). `options()` returns the app's `Options` — its `title`/`window`/dev-watch — so it is the **single source** of the window size/title: a `main.rs` that needs to customize (e.g. add a `theme_file`, as `examples/gallery` does) builds on `options()` rather than re-declaring `Options::new(title, window)`, so the two can't drift. It contains no logic and admits none — every field is a literal or a path, so there is nothing in it to test or to break. The same bundle feeds the windowed shell, the harness (`Harness::render(Counter::init())` is unchanged), release codegen, and `libra check` — exactly one place attaches a view to an app.

The `view:` literal is relative to the invoking `.rs` file. `build.rs` repeats it crate-root-relative (`views/counter.lx`) — acceptable duplication ([[PLAN-PACKAGE]] P0). Debug watch concatenates `CARGO_MANIFEST_DIR + "/src/" +` that literal, so shipping apps use `../views/….lx` from `src/lib.rs`; the shell polls the view *directory* so a composed component edit reloads too ([[PLAN-SDK]] S3). `libra new` writes this shape. `libra.toml` remains the manifest of record for windows/permissions/identity in multi-window apps (§26.3); `app!` is the single-window shorthand.
