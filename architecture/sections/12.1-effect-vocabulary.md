# 12.1 The Effect Vocabulary

## In this vault

- Parent: [[12-effects-runtime]]

## In code

- `crates/libra-core/src/lib.rs` — the `Effect` enum (Http, Kv*, Timer, Random, SetTheme, ClipboardSet, PickFolder, PickFile, SaveFile, Notify, Process, Spawn, OpenUrl, Dialog, Share, WindowOp)

---

```rust
pub enum Effect {
    // Network
    Http      { req: HttpRequest, on_done: ActionCtor<HttpResult> },
    WsConnect { url: Url, stream: StreamId },              // events arrive via Sub::stream
    WsSend    { stream: StreamId, data: Bytes },

    // Persistence ([[13-persistence|§13]])
    KvGet     { key: Key, on_done: ActionCtor<Option<Bytes>> },
    KvSet     { key: Key, value: Bytes, on_done: Option<ActionCtor<KvResult>> },
    KvDelete  { key: Key },
    KvScan    { prefix: Key, on_done: ActionCtor<Vec<(Key, Bytes)>> },

    // Files & processes
    FileRead  { path: PathBuf, on_done: ActionCtor<io::Result<Bytes>> },
    FileWrite { path: PathBuf, data: Bytes, on_done: ActionCtor<io::Result<()>> },
    Spawn     { command: Command, stream: StreamId },         // stdout/stderr as stream events

    // Time & entropy (keeping actions pure)
    Timer     { after: Duration, action: Action },
    Interval  { every: Duration, id: TimerId, action_ctor: ActionCtor<Instant> },
    CancelTimer { id: TimerId },
    Random    { bytes: usize, on_done: ActionCtor<Vec<u8>> },

    // Platform
    Clipboard(ClipboardOp), Dialog(DialogSpec, ActionCtor<DialogResult>),
    Notify(Notification), OpenUrl(Url), Share(ShareRequest), SetTheme(ThemeId),
    WindowOp(WindowOp),                                    // resize, title, fullscreen…

    // Data plane ([[14-data-plane|§14]])
    IngestOpen  { source: SourceSpec, series: SeriesHandle },
    IngestClose { series: SeriesHandle },
}
```

`ActionCtor<T>` is a function pointer `fn(T) -> Action` — serializable by registry id, so effect logs replay.

---

**Vocabulary growth (2026-07-19, PLAN-NATIVE-INTEGRATIONS):**
`Effect::ClipboardSet { text, on_done? }` — put text on the OS
clipboard; shell-handled (arboard, like `SetTheme` — never reaches the
worker pool), acked with a typed `ClipboardResult` when a ctor is
given. Harness: `fx::clipboard_set()` + `resolve_clipboard` — the
first platform effect landed with full harness parity, the template
for `OpenUrl`/`Dialog`/`Notify` (N1–N3).

**Vocabulary growth (2026-08-25):**
`Effect::PickFolder { on_done }` — native folder sheet (`rfd` on the
UI thread, same intercept as ClipboardSet). Continuation is
`FolderPick::Picked(path)` or `Cancelled`. Harness:
`fx::pick_folder()` + `resolve_folder_pick`. Gloss Browse uses this
to open a vault without typing a path.

**Vocabulary (not an Effect, 2026-08-25):** native menubar / context
menus are an `App::menu` / `context_menu` projection ([[19.3-native-menus|§19.3]],
PLAN-NATIVE-INTEGRATIONS N7). Clicks enter as ordinary actions. Nothing
new on `Effect`.

**Shipped:** `Effect::Sample { series, t_ms, value }` writes one point
into that series' ring. The runtime pushes it (§14.2). `update` does
not keep the value. Lima uses it for per-VM CPU, memory, and disk.

**Vocabulary growth (PLAN-NOTIFY, PLAN-RESIDENCY):** `Effect::Notify { note, on_activate?, on_done? }` is shell-handled via `notify-rust`. A click dispatches `on_activate`. A repeated `tag` is the replace key (Linux numeric id, macOS UserNotifications string id). `cargo run` on macOS and an unpackaged Windows build return `Unsupported` rather than pretending a banner was shown. `Effect::WindowOp` is `Show` / `Hide` / `Raise` / `Quit`. `Effect::LoginItem` and `Effect::LoginItemQuery` report on-disk autostart as `LoginItemResult`. Harness: `fx::notify` / `fx::notify_tag`, `activate_notification`, `fx::window_op`, `fx::login_item` / `resolve_login_item`, `h.tray` / `h.click_tray`.

**Vocabulary growth (PLAN-NATIVE-INTEGRATIONS N1, N2, N4, N6):** `Effect::OpenUrl { url, on_done? }` opens `http`, `https`, or `mailto` with the host opener (`/usr/bin/open`, `xdg-open`, `rundll32` url.dll). Other schemes fail before a process starts. `Effect::Dialog { spec, on_done }` is an OS alert or confirm (`rfd`); the in-tree `<Dialog>` overlay is markup and stays on the paint path. Linux alerts need zenity and otherwise return `Unsupported`. `Effect::Share { text, url?, on_done? }` writes the payload through the same clipboard path as `ClipboardSet` and acks `Copied`. There is no OS share sheet. `Effect::PickFile` and `Effect::SaveFile` are `rfd` sheets; a suggested save name is a file name, not a path. `Effect::WindowOp` adds `Title`, `Fullscreen`, and `Resize` beside Show/Hide/Raise/Quit. A refused title or size is not applied. Fullscreen does not enter the display list. Harness: `fx::open_url` / `fx::open_url_to`, `fx::dialog`, `fx::share`, `fx::pick_file`, `fx::save_file`, `h.chrome()`, `resolve_open_url` / `resolve_dialog` / `resolve_share` / `resolve_file_pick`. Headless acks `Unsupported("headless")`.

**Shipped (PLAN-STREAM-DELIVERY D1–D4):** `Effect::Spawn` /
`Effect::CloseStream` stream command output as `StreamEvent`s to a
mounted `<Stream>`. Same `CommandSpec` rules as
[[12.6-the-process-effect|§12.6]]. `Effect::Process` stays the
run-to-completion form. `Sub::Stream` (D5) and the aws-login device-code
screen (D6) are not built yet.
