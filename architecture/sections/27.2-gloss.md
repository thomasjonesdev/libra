# 27.2 Gloss

## In this vault

- Parent: [[27-first-party-applications]]
- Product docs: `applications/gloss/docs/`

## In code

- `applications/gloss/crates/gloss-core` — vault paths, parse, patch layer
- `applications/gloss/crates/gloss-cli` — list / cat / apply / undo
- `applications/gloss` — Libra editor shell

---

**Status: M0 usable.** A CLI apply/undo works against a fixture vault. The Libra
app lists notes, opens them in `<Textarea>`, and saves through the patch layer
via `Effect::Process` to the same `gloss` binary.

Gloss is a Markdown vault editor. Obsidian vaults are a first-class input.
Every write is a structured patch with `expect_hash`. Paths are
`(RootId, RelPath)` only. The core crate has no UI types.

The v1 editor is Libra `<Textarea>` (PLAN-TEXTAREA stage 1), not CodeMirror.
A markdown-aware crate (wikilink paint, ghost text) is the next framework
gap when Tab lands. File I/O is still Process-to-self, not `Effect::File*`.
That vocabulary extension is the honest next framework change (§12.1).
