Libra's desktop target is **macOS + Windows + Linux**. The product contract is two sentences:

1. **Content is identical.** The same `State` produces the same display list and the same framebuffer bytes on every OS ([[09.2-canonical-executor|§9.2]]). Nothing environment-dependent (system fonts, GPU, wall clock, OS appearance) enters the paint path.
2. **Chrome is native, and it is explicit.** Window chrome, menus, dialogs, clipboard, tray, notifications, and other OS-owned surfaces stay off the paint contract ([[19-platform-integration|§19]]). Every such capability is implemented with the host OS API on **each** desktop OS it applies to, or it fails honestly (typed `Unsupported` / harness-visible absence). **Silent no-ops are a bug.**

Cross-compilation of windowed apps and ship bundles is **deferred** ([[20-packaging|§20]]). You build and package on the host you ship for. That is a packaging constraint, not a license to ship a weaker shell on Windows or Linux.

First-party apps may choose a narrower OS (Gloss sidecar/MLX is macOS-only). That is an **app** decision. The framework is three-OS.

## Status vocabulary

| Word | Meaning |
|---|---|
| **Supported** | Implemented and intended on that OS |
| **Partial** | Implemented with a documented gap that this note requires closing |
| **Planned** | Specified; not shipped |
| **Unsupported** | No path today — must become Supported, a documented native equivalent, or typed `Unsupported` |
| **Native-only** | Must run on that host (packaging) |

## Content (must stay identical)

| Capability | macOS | Windows | Linux |
|---|---|---|---|
| Layout → `DrawCmd` → tiny-skia PNG | Supported | Supported | Supported |
| Bundled fonts (no system fallback by default) | Supported | Supported | Supported |
| Headless harness + snapshot tests | Supported | Supported | Supported |
| HiDPI: scale cmds at present; canonical paint stays 1.0 | Supported | Supported | Supported |
| softbuffer blit of that framebuffer | Supported | Supported | Supported |

A snapshot recorded on Linux must match macOS and Windows. A mismatch is a pin/toolchain bug, not an OS feature ([[15.1-determinism-contract|§15.1]], [[15.8-ci-shape|§15.8]]).

## Chrome — specified, not shipped (every OS, no silent skip)

These stay **Planned** on all three until the named plan lands. When they land they follow the same rule: native API per OS, or typed `Unsupported` — never a compile-and-discard stub.

| Capability | Plan | OS-native notes when they land |
|---|---|---|
| IME / CJK composition | [[PLAN-TEXTAREA]] stage 2 | `WindowEvent::Ime` through the shell; v0.1 bar ([[10.1-text-entry|§10.1]]) |
| Touch + OSK | [[19.1-touch|§19.1]], [[PLAN-TEXTAREA]] stage 3 | Linux tablets are in-scope; not mobile ([[24-non-goals|§24]]) |
| `Effect::Notify` | [[PLAN-NOTIFY]] | Linux D-Bus works without a bundle; macOS needs signed `.app` + consent; Windows needs a registered AppUserModelID. Dev must return `Unsupported`, not pretend |
| Tray / close-to-tray / single instance / launch-at-login | [[PLAN-RESIDENCY]] | R1 gate is macOS+Linux first; Windows tray still required before the row is **Supported**. Lock file (unix) / named mutex (Windows); XDG `.desktop` / Run key / `SMAppService` |
| File open/save, alert `Dialog`, `OpenUrl`, `Share` | [[PLAN-NATIVE-INTEGRATIONS]] N1–N4 | `rfd` / `open` / `xdg-open` / `ShellExecute` |
| `Effect::WindowOp` (show/hide/raise/quit, title, fullscreen) | N6 + R3 | |
| Follow OS light/dark appearance | deferred | App `SetTheme` only today; auto-follow is not a silent read of the OS |
| Multi-window | [[26-open-questions|§26]] #3 | Designed; not v1 |
| Global hotkeys | unclaimed | In the §19 table; no plan |

## Packaging (host-native; not a rustc triple)

| | macOS | Windows | Linux |
|---|---|---|---|
| Default `libra package` formats | `.app` + `.dmg` | NSIS | `.deb` + AppImage |
| Status | Shipped | Shipped | Shipped |
| Signing | Developer ID + optional notarization | Optional Authenticode | Reserved |
| Cross-compile from another OS | **Native-only** | **Native-only** | **Native-only** |
| Not implemented | Universal fat binary | MSI | RPM / Flatpak / Snap |

`--target macos|windows|linux` selects a **bundle format**. `validate_package_target` errors if host ≠ target. There is no zig/`cross`/sysroot story in-repo. `libra build` forwarding `cargo -- --target <triple>` is undocumented and not a supported path.

## Closing the gaps (do not build a fourth way)

Work that is **not** already owned by notify / residency / textarea / N1–N7:

| Gap | Required handling |
|---|---|
| Linux muda attach is a no-op | Real GTK (or documented typed refusal). Compiling gtk just to discard the menu fails this note |
| Wayland clipboard | Enable arboard Wayland data-control, or fail honest under a compositor without XWayland |
| Frameless on Windows / Linux | Native frameless / CSD, or typed refusal when `Options.frameless` is set on that OS |
| `cmd` Super-or-Ctrl | Either keep it as an **explicit** v1 binding (document it in §19.2) or split to match the vault's Super/Ctrl table — do not leave the two paths disagreeing quietly |
| Process `Signalled` on Windows | Stay Partial with a typed status, or map what Win32 actually has — do not invent signals |

Existing plans must implement **all three** desktop OS (or return typed `Unsupported` on the ones that cannot) when they land. Linux-first notify (NT1) and macOS+Linux-first tray (R1) are **sequencing**, not permission to ship a permanent silent stub on the remaining OS.
