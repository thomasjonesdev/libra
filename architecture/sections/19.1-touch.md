# 19.1 Touch

## In this vault

- Parent: [[19-platform-integration]]

---

Target hardware includes touch-first Linux tablets, so touch is a Phase 1–2 concern:

- **Gesture recognizer** in `libra-components`: tap, double-tap, long-press, drag, momentum/fling scroll (with the scroll fast path of [[09.3-damage-layers|§9.3]]), and pinch — pinch is wired into Chart zoom and Canvas transforms. Gestures resolve to ordinary actions; the component-test harness synthesizes gesture sequences, so touch interactions are as testable as clicks.
- **Hit-target tokens**: `touch.target.min` (44 logical px default) enforced by `libra check --a11y` on interactive components; a `touch`/`glove` density mode scales targets and spacing up the same way `compact` scales down.
- **On-screen keyboard — the honest gap**: winit delivers touch events but does not summon an OSK, and Linux OSK integration (squeekboard/onboard/portal) is fragmented. The reliable path: a **framework-owned OSK component** (deterministic, themeable, testable, layouts for text/numeric/hex) that Input/Textarea summon on touch focus; system-OSK integration is an opt-in behind `libra.toml [platform.linux] osk = "system"`. Risk tracked in [[25-risks|§25]].
- **Hover-independence audit**: `libra check` flags any interaction reachable only via hover (tooltips get long-press equivalents automatically).
