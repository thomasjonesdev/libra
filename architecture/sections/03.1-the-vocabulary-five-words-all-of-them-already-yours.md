# 3.1 The vocabulary (five words, all of them already yours)

## In this vault

- Parent: [[03-mental-model-react-to-libra]]

---

Libra's entire authoring surface is described by five nouns, each chosen to mean what a frontend developer already thinks it means:

| Word | Meaning in Libra | Where you know it from |
|---|---|---|
| **State** | The single app-state struct — the one source of truth | React state, the Redux store's state |
| **Action** | One recorded state change. *Authored* as a plain method on `State`; *recorded and replayed* as a serializable enum value ([[05.2-what-the-macro-generates-one-expansion-no-magic|§5.2]]) | Redux actions — except here they are generated, never hand-written |
| **Effect** | A *description* of I/O returned by an action; the runtime executes it, tests intercept it | `useEffect`'s job, done as data |
| **Component** | Everything that renders: the built-in catalog, `.lx` compositions, Rust components | React components |
| **View** | A `.lx` file — the declarative markup projection of `State` | JSX, minus embedded logic |

Supporting cast, same familiarity rule: **props**, **slices** ([[05.7-scaling-state-slices-not-fragmentation|§5.7]]), **subscriptions** ([[12.2-subscriptions|§12.2]]), the five **test kinds** ([[15-testing-architecture|§15]]), and "the **store**" as the informal name for `State` + its actions, as in Redux/Zustand.

Two deliberate naming judgments:

- **Actions, not "state", for the change vocabulary.** The things you write to define state changes live *on* the `State` struct as methods, so the mental model reads as "state and the ways it changes" — but the recorded values themselves are named *actions*, because calling an event "state" would collide with the state it changes. This is precisely the Redux frame every React developer already carries: state + actions + reducer, with the reducer generated ([[05.2-what-the-macro-generates-one-expansion-no-magic|§5.2]]).
- **Retired jargon.** *Model*, *Msg*, *update*, *Cmd*, *widget*, and *tier* no longer appear on the authoring surface. The Elm loop those words described is still exactly what runs — [[05.2-what-the-macro-generates-one-expansion-no-magic|§5.2]] shows the expansion — it just no longer names the API.
