# 6.2 The Closed Grammar

## In this vault

- Parent: [[06-view-and-markup]]

## In code

- `crates/libra-markup/src/lib.rs` — the grammar the parser accepts
- `crates/libra-interp/src/lib.rs` — how each construct binds against state

---

- **Bind** state fields and paths: `{count}`, `{user.name}`, `{items.len()}` (a fixed whitelist of pure accessors: `len`, `isEmpty`, formatting — camelCase in markup per [[03.3-naming-conventions|§3.3]]). Collection fields (`Vec<T>`) bind as iterable paths for `<for>`; there is no index expression (`{series[3]}` is not grammar — iterate, or model a named field).
- **Dispatch** actions by name, with payloads from bindings or literals: `onPress={increment}`, `onChange={filterChanged(value)}` (`value` is the control-provided payload), `onPress={select(item.id)}`. Handlers bind to the reflected action names of [[05.2-macro-expansion|§5.2]], exposed in camelCase per [[03.3-naming-conventions|§3.3]] (`fn filter_changed` binds as `filterChanged`).
- **Declare** ongoing sources: `<Frames onTick={frame} />`, `<Interval every={1000} onTick={poll} />`, `<Stream id={feed} onEvent={packet} />` — invisible source elements, subscribed while mounted, cancelled on unmount ([[12.5-declarative-subscriptions|§12.5]]).
- **Conditionals**: `<if test={connection.isLive()}>…<else>…</if>` — tests are bindings or whitelisted predicates; enum variants get generated `is*` predicates (camelCase in markup, [[03.3-naming-conventions|§3.3]]).
- **Iteration**: `<for each={items} as="item" key={item.id}>…</for>` — `key` is required when the collection can reorder; the reconciler uses it for identity.
- **Composition**: `<LogPanel entries={log.visible} onSelect={logSelected} />` — invoking another `.lx` view or Rust component with typed props.
- **Slots**: `<Card><slot/></Card>` children pass-through.
- **Format strings**: `{count:>6}` / `{temp:.2}` — Rust `format!` spec subset, compiled, no runtime parse.

---

## Implemented today (vs the vision above)

The bullets above are the target grammar. What both engines actually support now:

- **Bind**: whole-value fields `{count}` / `{name}`; **nested ReflectState dots** `{user.name}` (recurse through nestable struct fields — leaf/generic types stay whole-value only); **accessor whitelist** `{items.len}` / `{items.len()}` / `{name.isEmpty}` on `String` and `Vec<_>` (camelCase; optional empty `()`).
- **Dispatch**:
  - unit handlers `onPress={increment}`;
  - control-payload handlers `onChange={draftChanged}` (the control supplies the `String`);
  - **item-scoped handlers** `onPress={toggle(loopVar)}` **and** `onPress={complete(loopVar.field)}` — the resolved Display of the whole loop item or one of its reflected fields becomes the action's `String` payload. Parsed as `AttrValue::Call` (libra-markup), resolved and validated (must be a `String`-payload action; arg must be the in-scope loop variable or `loopVar.field` with one segment) in both engines, carried on `ViewNode::Button.on_press_arg` → `Item.on_press_arg`, dispatched via `ReflectAction::action_with_str` by harness and shell. Drift guards: `for_actions` (whole-value) and `for_item_fields` (structured fields).
- **Iterate**: `<for each={items} as="x" key={x}>` or `key={x.id}` — key is the loop variable itself or one field on it (identity data for a future reconciler; layout still rebuilds fully). Opaque element types (`Vec<String>`, `Vec<SeriesHandle>`) keep whole-value Display iteration via `ReflectState::collection` / `collection_rows` with empty field maps. Structured element types (`Vec<T>` where `T: ReflectState + Display`, typically `#[derive(LibraReflect)]`) expose named fields for `{x.field}` / `key={x.field}` / handler args. One path segment only — `x.a.b` is a span-diagnosed error.
- **Conditionals**: `<if test={running}>…<else>…</else></if>` — `test` is a bool field (top-level or nested dot) or `isEmpty` on a string/collection. Display `"true"` / typed bool / `.is_empty()` in codegen. Optional single trailing `<else>`. Expands away in both engines (no `ViewNode::If`). No expressions, enum `is*` predicates, or loop-scoped tests yet.
- **Not built**: format specs, composition/slots, nested loop-field paths, `test={path.isLive()}` / enum `is*` predicates.
- **Sources**: `<Frames>`, `<Interval every={ms} onTick={…}>` (Instant payload; shell recurring timers), `<Stream id={…} onEvent={…}>` (mount/query v1 — Ws event delivery later). See [[PLAN-SOURCES]].
- **Layout chrome** (PLAN-CATALOG wave 1, 2026-07-16): `<Spacer/>` (spring) / `<Spacer size={px}/>`, `<Separator/>` / `<Separator vertical/>` (1px `theme.hairline`), and `width={px}` on `<Column>`/`<Row>` for fixed pane sizing. Conformance fixture: `chrome.lx`.
- **Weighted grow** (2026-07-17): `grow={2.5}` on `<Column>`/`<Row>` — proportional pane shares, responsive under window resize (the bare `grow` flag ≡ `grow={1}`). Same `chrome.lx` fixture.
- **`<ListItem title={…} subtitle={…} meta={…} selected={…} onPress={…}>`** (2026-07-17): pressable row; text attrs take literals or bindings (loop fields included); `selected` is a bool binding under the `<if>` Display-`"true"` rule, or a bare flag; `onPress` supports the item-scoped `action(loopVar.field)` form. The whole row is the press target. Conformance fixture: `list_textarea.lx`.
- **`<Textarea value={…} placeholder="…" onChange={…} testId="…">`** (2026-07-17, PLAN-TEXTAREA stage 1): multi-line controlled entry, the Input contract verbatim — hard newlines only (no soft wrap yet). Same fixture.
- **`<Dialog title={…} onDismiss?={…} testId?="…">`** (2026-07-19, PLAN-CATALOG / PLAN-NOTES-APP M6): the in-tree modal — full-viewport `theme.scrim` + centered `surface_raised` panel holding ordinary markup children. Mount/unmount is the app's `<if>`; `onDismiss` (unit action) makes the scrim click-to-dismiss, otherwise it swallows clicks (modal barrier in hit testing). Detached overlay layout: paints on top wherever it sits in the markup. Conformance fixture: `dialog.lx`.
- **`<Split fraction={0..1} onResize={…} testId="…">`** (2026-07-19, PLAN-CATALOG / PLAN-NOTES-APP M5): two-pane draggable splitter — `fraction` binds a typed State f32 (the `<Progress value>` rule), `onResize` is a String-payload action carrying the new fraction, exactly two children. Model-owned (the controlled shape). Conformance fixture: `split.lx`.
- **`<ContextMenu onDismiss?={…} testId="…">`** + **`onMenu={…}` / `onMenu={action(loopVar.field)}` on `<ListItem>`** (2026-07-19, PLAN-CATALOG / PLAN-NOTES-APP M7): right-click menus — the Dialog overlay machinery with an invisible barrier and a panel floated to the **menu anchor**, a deterministic input like focus/hover/scroll (shell: the right-click point; harness `right_click`: the item's center; snapshots pin it). Menu items are ordinary markup. Conformance fixture: `menu.lx`.
- **Catalog parity wave** (2026-07-19, PLAN-CATALOG audit follow-through): `<Alert tone title>body</Alert>` (status-token callout), `<Card>`/`<Panel>` (surface containers, Column semantics + token padding/gap defaults), `<Skeleton width? height?/>`, `<Avatar name size?/>`, `<Switch checked={bool} onToggle>`, `<Checkbox checked={bool} onToggle>label</Checkbox>`, `<Radio selected={bool} onSelect|onSelect(loopVar.field)>label</Radio>` (groups via `<for>`), `<Drawer side="left|right|bottom" onDismiss?>` (bottom = the reference's Sheet; Dialog overlay machinery). Bool attrs share the `<if>` Display-`"true"` rule. Conformance fixtures: `surfaces.lx`, `toggles.lx`.
- **Nav wave** (2026-07-20/21): `<Breadcrumb>` (`BreadcrumbItem` children, auto-inserted "›" chevron, trailing `current` non-pressable), `<Pagination current={u32} total={u32} onPage={…}>` (fully generated — Prev/Next + a windowed page run with ellipsis, the windowing logic lives once in libra-components so both engines share it byte-for-byte), `<Stepper current={u32}>` (`StepperItem` children; completed/active/pending status is *derived from index vs current*, never an attr — connector auto-inserted), `<Timeline>` (`TimelineItem` children carry `done` directly; connector auto-inserted). Conformance fixture: `nav.lx`.
- **`<Slider value={0..1} onChange={…} testId="…">`** (2026-07-19/20): model-owned continuous control — typed value (the `<Progress>` rule), String-payload `onChange`; the shell's Split-drag machinery generalized to a `DragTarget` enum covering both divider gutters and slider tracks. Harness `set_slider`.
- **`<Tooltip text={…} position?="top|right|bottom|left">child</Tooltip>`** (2026-07-19/20; `position` 2026-08-26): a floating label riding the deterministic hover input — hidden at rest (every existing snapshot untouched), painted in a second pass above everything when the hover point (shell cursor / harness `hover(sel)`) is inside the wrapper. Default `position` is `top`. Conformance fixture: `slider_tooltip.lx`.
- **`<Search value={…} placeholder="…" onChange={…} onSubmit?={…} testId="…">`** (2026-08-25, PLAN-CATALOG wave 3): Input chrome + submit. `onChange` is the String-payload live edit; optional `onSubmit` is a unit action fired on Enter (query already in State). Live-filter UIs omit it. Conformance fixture: `search.lx`.
- **`<Chip selected?={…} onPress?={…} onRemove?={…}>Label</Chip>`** (2026-08-25, PLAN-CATALOG wave 5): pressable pill. `selected` is the `<if>` Display-"true" bool; `onPress` / `onRemove` are optional and accept the item-scoped Call form. `onRemove` paints a trailing × (`testId`-remove). Conformance fixture: `chip.lx`.
- **`<Tabs>` / `<Tab selected?={…} onPress?={…} onClose?={…}>Label</Tab>`** (2026-08-25, PLAN-CATALOG wave 7): editor tab strip. `selected` is the `<if>` Display-"true" bool; handlers accept the item-scoped Call form. `<for>` / `<if>` are legal children (via `resolve_children`) — Gloss binds `tab_rows` this way. `onClose` paints a trailing × (`testId`-close). Conformance fixture: `tabs.lx`.
- **`<Toast tone? title? onDismiss?>body</Toast>`** (2026-08-25, PLAN-CATALOG wave 7): detached non-modal overlay (bottom-right). Mount via `<if>`; `onDismiss` is a unit action on the × (`testId`-close). Auto-timeout is an app Timer / `<Interval>`, never a paint-path clock. Conformance fixture: `toast.lx`.
- **`<Toolbar vertical? compact? background?=…>`** (2026-08-25, PLAN-CATALOG wave 7): chrome strip. Default is a full-width row with a bottom hairline and `surface_raised` fill; `vertical` fills height with a right hairline (Gloss left rail). `background` names a theme color token (`surface`, `surface_raised`, `bg`, `secondary`, `transparent`). Children are ordinary markup (`Button`, `Tabs`, `Spacer`). Conformance fixture: `toolbar.lx`.
- **`<Icon name="plus" muted?>`** (2026-08-25, PLAN-CATALOG): closed glyph set painted as polylines. `Button icon="plus"` is the pressable form (Gloss rail). Conformance fixture: `icon.lx`.
- **`<StatusBar>`** (2026-08-25, PLAN-CATALOG wave 7): footer chrome. Full-width row, hairline on top. Children are ordinary markup (Gloss: muted `Text` slots). Conformance fixture: `statusbar.lx`.

`examples/todos` is the reference for structured item fields + item-scoped handlers; `examples/dashboard` for display-only whole-value `<for>`. `<if>`/`<else>` is exercised by the `if_else` conformance fixture (both branches).
